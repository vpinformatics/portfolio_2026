# VP Informatics — Marketing Site

Marketing / portfolio website for **VP Informatics**, a manufacturing software studio that builds custom production planning, ERP-gap, inventory, dispatch, and industrial IoT systems for factories.

The homepage (hero, outcomes ticker, solution cards, portfolio summary, process, FAQ/decision framework, and a contact form) plus four standalone case-study pages, built with **Next.js 14 (App Router)**, **React 18**, and **Tailwind CSS**.

## Tech stack

- [Next.js 14](https://nextjs.org/) — App Router, static export–friendly
- React 18
- Tailwind CSS 3
- No external UI/component libraries — icons are inline SVGs, all content is plain data arrays inside `components/App.jsx`
- `sharp` (dev dependency only) — used solely by `scripts/gen-assets.js` to regenerate the favicon/OG image; not part of the app runtime

## Project structure

```
app/
  layout.jsx                # <html>/<body> shell, next/font (Manrope/Sora), metadata (title, OG, Twitter, robots)
  page.jsx                   # renders <App/> + ProfessionalService/FAQPage JSON-LD (homepage)
  globals.css                # Tailwind directives + theme (light/dark) CSS + keyframes
  sitemap.js                  # generates /sitemap.xml (home, /case-studies, each case study)
  robots.js                    # generates /robots.txt
  manifest.js                   # generates /manifest.webmanifest
  icon.png, apple-icon.png, opengraph-image.png  # favicon / OG preview image (generated by scripts/gen-assets.js)
  case-studies/
    page.jsx                       # case study index — lists all 4, own metadata + breadcrumb JSON-LD
    [slug]/page.jsx                 # one route per case study — generateStaticParams + generateMetadata + breadcrumb JSON-LD
components/
  App.jsx              # homepage: hero, sections, portfolio summary, FAQ, contact form
  SiteHeader.jsx         # nav + theme toggle + mobile menu (shared across all pages, owns its own state)
  SiteFooter.jsx          # footer (shared across all pages)
  CaseStudyArticle.jsx     # the detailed case-study article markup, shared by each /case-studies/[slug] page
  Analytics.jsx             # optional GA4 loader — inert unless NEXT_PUBLIC_GA_MEASUREMENT_ID is set
  SvgIcon.jsx                 # inline icon set
  VPLogo.jsx                   # logo with graceful text fallback
  AnimatedSection.jsx           # IntersectionObserver-based scroll reveal wrapper
  siteData.js                    # single source of truth: site URL, org description, nav links, FAQ, solution cards, case-study content — feeds both the UI and every JSON-LD block
scripts/
  gen-assets.js   # regenerates icon.png / apple-icon.png / opengraph-image.png from the real logo (see SEO section)
```

All page copy (hero slides, outcome stats, solution cards, portfolio summary cards, the four case-study articles, FAQ) lives as plain JS data in `components/siteData.js` (hero slides stay in `components/App.jsx` since they include JSX) — edit those arrays to change content, no markup restructuring needed.

Dark/light theme is toggled via a `theme-light` / `theme-dark` class on `<body>`, persisted to `localStorage`, and styled with plain CSS overrides in `app/globals.css` (not Tailwind's `dark:` variant).

## Running locally

Requires Node.js 18.17+ (Node 20+ recommended).

```bash
npm install
npm run dev
```

Visit **http://localhost:3000**.

## Building for production

```bash
npm run build
npm run start
```

`npm run build` produces an optimized production build in `.next/`. `npm run start` serves that build (defaults to port 3000; pass `-p <port>` to change it).

## Publishing / Deploying

Any Node.js hosting platform that supports Next.js works. The simplest options:

### Vercel (recommended, zero-config)
1. Push this repo to GitHub.
2. Import the repo at [vercel.com/new](https://vercel.com/new).
3. Vercel auto-detects Next.js — no build settings needed. Every push to `main` deploys automatically.

### Any Node server (VPS, Docker, etc.)
```bash
npm install
npm run build
npm run start   # serves on port 3000 by default
```
Put this behind a reverse proxy (nginx, Caddy) with your domain and TLS.

### Static export
If the site stays fully client-rendered (no server-only features are added), you can export static HTML:
```bash
npx next build && npx next export
```
This generates an `out/` directory that can be hosted on any static host (Netlify, GitHub Pages, S3, etc.).

## SEO

The site is configured for production SEO out of the box:

- **Metadata** (`app/layout.jsx`, plus per-page `metadata`/`generateMetadata` in `app/page.jsx` and `app/case-studies/**`): title template (`%s | VP Informatics`), description, keywords, canonical URLs, `robots` directives, Open Graph, and Twitter card tags — all built from `https://vpinformatics.in` (`components/siteData.js`).
- **Dedicated, indexable case-study pages** — `/case-studies` (index) and `/case-studies/{slug}` (one real route per industry vertical: `printing-packaging`, `pcb-electronics`, `textile-embroidery`, `iot-embroidery`), each statically generated (`generateStaticParams`) with its own title/description/canonical/OG tags and `BreadcrumbList` JSON-LD. The homepage only shows short summary cards linking to these — the full case-study detail lives solely on its own route, so there's no duplicate-content split between two URLs.
- **Structured data**: `ProfessionalService` (org info, logo, and a `Service` offer catalog generated from the solution cards) + `FAQPage` (mirrors the on-page FAQ accordion) on the homepage (`app/page.jsx`); `BreadcrumbList` on every case-study page. All sourced from `components/siteData.js` so the JSON-LD can't drift from what's visibly rendered.
- **`/sitemap.xml`** and **`/robots.txt`** — generated by `app/sitemap.js` / `app/robots.js`, covering the homepage, the case-study index, and all four case-study routes.
- **`/manifest.webmanifest`** — generated by `app/manifest.js`.
- **Self-hosted fonts** via `next/font/google` (`app/layout.jsx`) — Manrope and Sora are bundled and served from the same origin instead of a render-blocking Google Fonts `<link>`, which helps FCP/LCP.
- **Favicon / Apple touch icon / Open Graph preview image** — `app/icon.png`, `app/apple-icon.png`, `app/opengraph-image.png`, generated from the real "VP" logo monogram by `scripts/gen-assets.js` (downloads the logo, crops the monogram, composites it onto a white tile for the icons and a dark gradient OG card with the hero headline). Re-run `node scripts/gen-assets.js` after changing the logo or the OG headline copy in that script. Next's dynamic `next/og`-generated-route approach isn't used here because `next/og`'s `ImageResponse` currently crashes at build time on Windows (a `@vercel/og` bug resolving its default font via a malformed `file://` URL) — pre-generating static PNGs sidesteps it.
- Single `<h1>` per page (hero headline on the homepage, case-study title on its own page); the hero slide shown on first paint is fixed (not randomized) so search engines and social-preview bots always see the same, consistent headline — the auto-rotating carousel still runs client-side afterward.
- Shared `<nav>`/`<footer>` (`components/SiteHeader.jsx`, `components/SiteFooter.jsx`) across every route, so navigation, theme toggle, and internal linking stay consistent whether a visitor lands on the homepage or a case study.
- **Google Search Console verification** — set the `GOOGLE_SITE_VERIFICATION` environment variable (the `content` value from the verification meta tag GSC gives you) and `app/layout.jsx` picks it up automatically; omitted entirely from `<head>` if unset.
- **Analytics** — set `NEXT_PUBLIC_GA_MEASUREMENT_ID` (a GA4 Measurement ID, e.g. `G-XXXXXXX`) and `components/Analytics.jsx` loads `gtag.js` via `next/script`; renders nothing if unset. Swap this component's contents if you'd rather use Plausible/Fathom/etc.

### Environment variables

Create `.env.local` (never commit it) for anything above that needs a real value:

```
GOOGLE_SITE_VERIFICATION=      # from Google Search Console
NEXT_PUBLIC_GA_MEASUREMENT_ID= # e.g. G-XXXXXXX, from Google Analytics
```

Before going live:
- Update `siteUrl` in `components/siteData.js` if the domain changes.
- Create a Google Search Console property for `vpinformatics.in`, set `GOOGLE_SITE_VERIFICATION`, then submit `/sitemap.xml` there.
- Decide on an analytics provider and set `NEXT_PUBLIC_GA_MEASUREMENT_ID` (or swap in your provider of choice).

## Contact form

The form posts to an external automation webhook (`https://automation.vpinformatics.in/webhook/ContactUsWeb`) with the submitted fields plus page URL and timestamp — see `handleSubmit` in `components/App.jsx`. It includes basic spam protection: a honeypot field (`website`, hidden from real users via off-screen CSS) and a simple arithmetic CAPTCHA, both checked client-side before the request fires. On success it shows a confirmation state for 5 seconds; on failure it shows an inline error and lets the visitor retry. "Schedule Strategy Consultation" links to `mailto:vpinformatics365@gmail.com`.
